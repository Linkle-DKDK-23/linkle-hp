# サイト構成案（v1 / 2026-11-18）

根拠は `research-seo.md`。順位は Yahoo! 検索1ページ目での確認で、Google 本体と検索ボリュームは未計測。

## 1. 目標キーワードの組み替え

| 元の目標 | 判断 | 狙う語 |
|---|---|---|
| 建設業 システム開発 | 維持 | 自社ページ + 比較メディア掲載の両面 |
| 建設 システム | 外す（株式会社建設システムの指名検索） | 建設業 業務システム 開発 / 建設業 システム オーダーメイド |
| {業種} システム | 業種により外す（足場=足場製品、塗装=塗装設備、解体=自動車リサイクル、荷揚げ=滑車が上位） | {業種} 管理システム / {業種} 業務システム / {業種} システム開発 |
| 造園 システム・内装 システム | 維持（裸の語でも業務ソフトの意図） | — |

title と H1 は「{業種}会社の業務システム開発」の型にする。本文に「{業種} システム」「管理システム」を自然に含めるので、裸の語で意図が合う検索にも拾われる。

## 2. サイトマップ

```
/                              トップ（建設業のDX・システム開発会社）
/construction-dx/              柱ページ: 建設業向けシステム開発の全体像
/industries/                   業種から探す（ハブ。全業種を業務課題の軸で一覧）
/industries/{slug}/            業種ページ
/works/                        開発事例
/works/niage-dx/               荷揚げ会社のDX事例（1日4時間削減）
/service/                      サービス一覧
/service/system-development/   受託開発の進め方
/service/web/                  Web制作（業種を問わない）
/guide/                        資料（サービスガイド）への入口
/about/ /recruit/ /news/ /contact/
```

スラッグはローマ字（niage, zouen, ashiba）。末尾スラッシュで統一。

## 3. 業種ページの出し方

「全業種を対象」というご要望と、Google のスパムポリシー（業種名を差し替えただけのページの大量公開は違反になりうる）を両立させるため、次の3段階にする。

| 段階 | 業種 | 扱い |
|---|---|---|
| 公開時（8本） | 荷揚げ・揚重 / 造園 / 鳶・土工 / 防水 / 解体 / 内装仕上 / 建築塗装 / 足場 | 単独ページ。業種固有の内容 3,000字以上 |
| 第2弾（中身が書けるものから） | 外構・エクステリア / 型枠 / 鉄筋 / 左官 / 屋根・板金 / リフォーム / 土木 / 舗装 / 設備 / 管工事 / 電気 / クレーン / 産廃 / 交通誘導警備 / 建機レンタル | 公開時はハブに掲載（各150〜250字）。Search Console の反応を見て単独ページ化 |
| ハブのみ | サッシ・建具 / タイル / 鉄骨 / 大工・工務店 / 保温 / 消防設備 / 電気通信 / 重量とび / 建材販売 | ハブでの言及にとどめる |

**全業種はハブページに最初から載る**ので、どの業種の方が来ても自分の業種が見つかる。単独ページは、その業種の言葉で書ける順に増やす。

## 4. 業種ページの型

1. リード（誰のどの業務を何で置き換えるか。3〜4文）
2. その業種の事務で起きていること（帳票名・現場用語で）
3. システムで一つにまとまる業務（業務フロー図）
4. 既製アプリが向く会社 / 専用開発が向く会社（正直に分ける）
5. 開発事例（荷揚げ事例との共通点 → 事例ページへ）
6. 進め方（短く。共通ページへ）
7. よくある質問（業種固有 4〜6問。費用は金額を出さず「何で決まるか」を書く）
8. 近い業種・業務課題
9. 相談する / 資料を見る

実績のない業種は「想定する構成例」と明記し、導入効果を装わない。

## 5. 資料導線と閲覧計測

- ヘッダー右に「資料を見る」を常設。トップ・柱ページ・全業種ページ・サービスページにも配置
- クリックは GA4 イベント（どのページのどの位置から開いたか）で計測
- guide.linkle.group 側にも同じ GA4 を入れ、ページ送り・読了・PDF ダウンロードを計測（クロスドメイン設定）
- 「誰が見たか」まで取る場合は、会社名とメールの入力フォームを挟む方式になる。**要判断**（閲覧数は減る）

## 6. AIO（AI検索）

Google 公式は AI 向けの特別施策（llms.txt、AI専用マークアップ）を不要としている。効く根拠があるのは次の3つ。

1. 通常の SEO（静的 HTML、構造化データ、会社情報の表記統一）
2. 他社に書けない一次情報（荷揚げ事例の内訳つき数値）
3. 外部での言及（比較メディア・企業DB・顧客サイト）

実施: Organization / Service / BreadcrumbList / FAQPage の構造化データ、AIクローラー許可、Google ビジネスプロフィール整備、発注ナビ・比較ビズ等への掲載。llms.txt は効果の根拠が弱いが、コストがほぼ無いので置く。

## 7. 要確認（ユーザー）

1. 荷揚げ事例の詳細: 会社規模、導入前の作業、4時間の内訳、開発期間、社名掲載やコメントの可否
2. 「無料で見本をつくる」は掲載してよいか（金額ではない）
3. 資料の閲覧計測は匿名のアクセス解析でよいか、会社名・メールの取得まで必要か
4. 社名表記は「Linkle株式会社」で統一でよいか
5. 比較メディア（発注ナビ等）への掲載申し込みを進めるか（有料の可能性あり）
