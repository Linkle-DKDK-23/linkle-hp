# SEO / AIO(LLMO) 調査レポート — 「建設業のDX・システム開発会社」としてのサイト刷新

- 調査日: 2026-11-18
- 対象: Linkle株式会社 コーポレートサイト刷新(Next.js 静的書き出し予定)
- 目的: 「建設業 システム開発」「{業種名} システム」での検索上位と、AI検索(AI Overviews / ChatGPT / Perplexity 等)での言及獲得

## 0. 先に結論

1. **「{業種} システム」という裸のキーワードは、多くの業種で狙う意味がない。** 「足場 システム」は足場製品(Iqシステム等)、「塗装 システム」は塗装設備、「解体 システム」は自動車リサイクル、「荷揚げ システム」は滑車の倍力システムが上位を占め、業務ソフトを探す意図ではない。狙うべきは「{業種} 管理システム」「{業種} 業務システム」「{業種} システム開発」。例外は「造園 システム」「内装 工事 システム」で、これらは裸のままでも業務ソフトが並ぶ。
2. **「建設 システム」は株式会社建設システム(KENTEM)の指名検索で、上位獲得は事実上不可能。** 目標から外すべき。
3. **「建設業 システム開発」の1ページ目は比較メディアと大手SIerが占める。** 自社ページで順位を取る努力と並行して、比較メディアへの掲載を取りに行くのが現実的(AI検索での言及にも効く可能性が高い)。
4. **受託開発会社が業種ページで食い込めている実例はある。** 「造園 システム開発」で受託開発会社2社が2位・3位。いずれも本文1,000〜2,500字程度で、顧客事例の数値は載っていない。実績数値を持つLinkleは内容で上回れる。
5. **AI検索向けの「特別な施策」はGoogle公式が不要と明言している**(llms.txt、チャンク化、AI専用マークアップ)。効くと根拠があるのは、通常のSEO、テキストでの明快な記述、外部サイトでの言及の3つ。
6. **業種ページは30本を一気に作らない。** 実績のある荷揚げを核に6〜8本から始め、業種固有の中身が書けるものだけ増やす。Google自身が「検索順位やAI回答を操作する目的の大量ページ」をスパムポリシー違反になりうると明記している。

## 3. 業種リストの設計

### 3.1 キーワードの型

業種ページごとに、titleとH1で狙う語を次の優先順で決める。

1. 「{業種} システム開発」— 受託開発の意図に最も近い。ただし足場のように物理製品が混ざる業種では効かない
2. 「{業種} 業務システム」「{業種} 管理システム」— 既製品を探す人が多いが、既製品で足りない層が流入する
3. 「{業種} DX」「{業種} アプリ 開発」— 補助的に本文へ

「{業種} システム」単体は、造園・内装・外構・警備・産廃などソフトの意図が成立する業種だけで意識すればよい。

### 3.2 業種候補(優先度つき)

優先度の基準は「需要の見込み × 競合の弱さ × Linkleが中身を書けるか」。検索ボリュームは未計測のため、需要は推測。「競合」欄で(確認)と付けたものは今回検索結果を見たもの、付けていないものは未確認の推測。

## 4. 業種ページの量産と品質

### 4.1 Googleの定義(根拠あり)

Google検索のスパムポリシーの記述。

- **誘導ページ(doorway abuse)**: 特定の類似クエリで上位表示するために作られ、最終目的地ほど役に立たない中間ページへ誘導するもの。例として「明確で閲覧しやすい階層よりも検索結果に近い位置に、実質的に似通ったページを作る」が挙がっている。
- **大量生成コンテンツの不正使用(scaled content abuse)**: 検索順位の操作を主目的に、価値の低い独自性のないページを大量に作ること。作成方法(AIか人か)は問わない。
- Googleの生成AI検索向けガイドにも、検索順位や生成AIの回答を操作する目的で大量のページを作らないこと、という記述がある。

つまり判定の軸は本数ではなく、**業種名を差し替えただけか、その業種の人にとって役立つ固有の情報があるか**。

### 4.2 低品質と判定されないための要件

| 要件 | 具体策 |
|---|---|
| 業種固有の内容がページの大半を占める | 業務の流れ、帳票名、現場用語、法令・制度をその業種の言葉で書く。共通部分(会社紹介、開発の進め方、CTA)は短くまとめ、共通ページへリンクする |
| 差し替えテストに耐える | 業種名を別の業種に置換して違和感なく読めるなら作り直す |
| ページが行き止まりでも中継でもない | 業種ページ単体で疑問が解決する。問い合わせページへ流すだけの構成にしない |
| 既製品との関係を正直に書く | その業種の既製SaaSを挙げ、既製品で足りるケースと専用開発が向くケースを分ける(NeoLogicの3択と同じ考え方) |
| 実績のない業種で実績を装わない | 荷揚げ以外は「想定する構成例」と明記する。架空の導入効果は書かない |
| 書けない業種は作らない | 固有の内容が800字に満たない業種は単独ページにせず、ハブページの一覧で触れるだけにする |
| 一度に出さない | 6〜8本で公開し、Search Consoleでインデックスと表示回数を見てから追加する |
| ナビゲーションから辿れる | グローバルナビに「業種から探す」を置き、ハブ経由で全業種に到達できる |

### 4.4 サイト構造とURL

```
/                                トップ(建設業のDX・システム開発会社)
/construction-dx/                柱ページ(建設業向けシステム開発の全体像)
/industries/                     業種から探す(ハブ)

/service/system-development/     受託開発の進め方
/service/web/                    Web制作
/about/  /recruit/  /news/  /contact/
```

- **スラッグ**: ローマ字(ashiba、zouen)を推奨。日本語URLは共有時にエンコードされて長くなる。英訳(scaffolding)より日本の業界人に馴染む。スラッグが順位に与える影響は小さいと考えられ、ここは好みの範囲。
- **末尾スラッシュ**: Next.js の静的書き出しで `trailingSlash: true` に統一し、canonical と sitemap.xml も同じ形に揃える。
- **内部リンク**:
  - トップ → 柱ページ、業種ハブ、事例
  - 業種ハブ → 全業種ページ(業務課題の軸でグループ化)
  - 業種ページ → 事例、近い業種2〜3本、柱ページ、問い合わせ
  - 事例ページ → 関連する業種ページすべて
- **パンくず**: ホーム > 業種から探す > 足場工事。BreadcrumbList の構造化データと一致させる。
- **現行ホスティングでの注意**: S3 + CloudFront で SPA 用のエラーページ設定(404を index.html に200で返す設定)が残っていると、存在しないURLがすべて200になりソフト404の原因になる。静的書き出しへの移行時に、存在しないURLが404ステータスを返すことを確認する。

**文章の書き方**(Googleは特別な書き方を不要としている。以下は人にもAIにも誤読されにくい書き方という一般的な原則で、引用率が上がる根拠があるわけではない)

- 各ページの冒頭で「誰が、誰に、何をするか」を主語つきの完全な文で書く。例:「Linkle株式会社は、東京・池袋のシステム開発会社です。建設会社ごとに専用の業務システムを一から受託開発しています。」

- 見出しは質問または名詞で内容を言い切る。指示語や凝ったコピーだけの見出しを避ける。
- 重要な情報を画像内の文字やアニメーションだけで表現しない。

**エンティティの整備**

- **表記の統一**: 現行サイトのtitleは「Linkle株式会社」、リポジトリのCLAUDE.mdでは「linkle株式会社」と大文字小文字が揺れている。登記上の表記を確認し、サイト、GBP、求人媒体、SNS、プレスリリースで一字一句揃える。住所表記(西池袋2-36-1 ソフトタウン池袋913号)と電話番号も同様。

**robots.txt**

検索用とユーザー起点のクローラーは許可する。学習用を許可するかは方針次第だが、言及されることが目的なら拒否する理由は薄い。

置いても害はないが、効果を示す根拠はない。作るなら10分で済む範囲にとどめ、優先度は最下位とする。

### 6.4 段階的な進め方

| 段階 | 内容 |
|---|---|
| 公開時 | トップ、柱ページ、荷揚げ事例、業種ハブ、優先度Aの業種ページ6〜8本、会社概要、構造化データ、sitemap.xml、Search Console 登録 |
| 公開後1〜2か月 | GBP整備、外部プロフィールの書き換え、比較メディアへの掲載申し込み |
| 公開後3か月 | Search Console で業種ページごとの表示回数と掲載順位を確認。表示が出ている業種の近縁から優先度Bを追加。表示が出ないページは内容を見直す |
| 継続 | 新しい開発事例が出るたびに事例ページを追加し、該当する業種ページの「想定構成例」を実例に差し替える |

コラムを運用しない場合、**新しい事例の追加が唯一の更新手段**になる。年に2〜3本でも事例ページが増える体制を作れるかが、中長期の順位を左右すると推測する。
