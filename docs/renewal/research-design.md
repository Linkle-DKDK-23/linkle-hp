制約として先に述べておくこと:

- 静止画キャプチャなので、**動きの質（イージング、速度、連動の滑らかさ）は判定できていません**。「動いていること」「構造としてピン留めがあること」までが確認範囲です。
- ヘッドレス環境では WebGL やローダーが止まるサイトがあり（Locomotive、Obys、basement は開幕画面から先に進まず）、これらのスクロール演出は未確認です。
- **受賞・ギャラリー掲載の裏取りは一部しかできていません。** SANKOU! / MUUUUU.ORG / Web Design Clip は該当ページを取得できず（404 または検索に出ず）、各サイトの掲載有無は未確認です。Awwwards で確認できたのは Garden Eight、SHIFTBRAIN、STUDIO DETAILS（制作会社として）、Locomotive、Igloo Inc のみ。
- スマートフォン表示は今回未調査です。

## 1. 先に結論（調査から言えること）

1. **「内容が主役」のサイトは、ファーストビューで事業を一文で言い切っている。** ベイジ「コンサル型ウェブ制作会社です。」、Arent「建設業界の課題をテクノロジーの力で、共に解決していく。」、ゆめみ「みんな知ってるあのサービスも、ゆめみが一緒に作ってます。」。英語の大見出しだけで始まる LIG・モンスターラボ・Garden Eight は、何の会社かが 1 画面目では伝わりにくい。
2. **明るい基調で緻密に見えるサイトの共通項は「薄い罫線・ドットグリッド・等幅フォントの小さなラベル・番号」。** Ramp、Attio、Vercel、ROUTE06 がこの型。派手な 3D ではなく、線と余白の精度で「ディテール」を出している。
3. **「縦にただ流れない」工夫の主流は、横スクロールではなく「左が固定・右が切り替わる」スティッキー構造。** Attio（sticky 6 要素）、Mercury（4）、グッドパッチ（9）で確認。左に項目リストが残るので、IT に詳しくない読者でも「今どこを読んでいるか」を見失わない。Linkle の読者層にはこれが最も安全な「スクロールの壊し方」。
4. **写真なしでも成立している国内例がある。** Arent（アイソメトリックのブロック）、LayerX（3D の積層ブロック）、ROUTE06（鉛筆画風イラスト）、mount（イラスト）、スパイダープラス（建設現場の線画）。いずれも明るい背景。
5. **建設系 B2B の信頼表現は 4 型。** 現場写真（アンドパッド、助太刀、Procore）／製品 UI（フォトラクション）／線画・ワイヤーフレーム（スパイダープラス、Buildots）／抽象ブロック（Arent）。写真が使えない Linkle は後ろ 2 つが現実的。
6. **導線は「資料 DL」と「問い合わせ」の 2 ボタンをヘッダーに常設するのが国内 B2B の定型。** ベイジ、ニジボックス、Arent、フォトラクション、助太刀で確認。ベイジはさらにサービス別に「サービス紹介 / 資料ダウンロード / お問い合わせ」をファーストビュー内に 3 列並べている。
7. **#6ccaf1 は白背景の文字色には使えない**（白とのコントラスト比はおよそ 1.9:1 で、本文に必要な 4.5:1 に届かない）。面・線・図形の色として使い、文字は濃紺〜墨色で組む前提にする必要がある。

## 4. 建設業向け B2B の「信頼感」と「分かりやすさ」の表現パターン

### 4-1. モチーフの抽象化（確認できた実例）

| 抽象化の仕方 | 実例 [実測] | Linkle での使い方 |
|---|---|---|
| **方眼・ドットグリッド**（方眼紙・図面用紙） | Arent（方眼の床）、Ramp、ROUTE06（カード内の方眼）、Buildots | ページ全体の地模様。濃度はごく薄く |
| **トンボ・かぎ括弧・十字マーク**（図面の基準点、測量の標点） | ROUTE06（四隅のかぎ括弧）、Buildots（黄色の十字） | 図版やカードの四隅、章の切れ目 |
| **ワイヤーフレーム線画**（設計図・BIM） | スパイダープラス（現場の線画）、Buildots（建物の黄色い輪郭）、Igloo（線画→立体） | 開幕アニメーション、背景 |
| **アイソメトリックのブロック**（躯体・積み上げ） | Arent（噛み合うブロック）、LayerX（積層ビル） | サービスの関係図、背景 3D |
| **斜めの切り返し線**（鉄骨のブレース、タワークレーン） | スパイダープラス | セクション境界 |
| **安全色**（黄 × 黒） | 助太刀、Buildots、スパイダープラスの黄線 | 水色が主役なので、アクセント 1 か所まで |
| **番号・工程**（工程表） | ROUTE06（03 信頼を築く）、モンスターラボ（01〜07）、LIG（01〜05） | 章番号、導入の流れ |
| **道具** | クラフトバンク（大工道具の写真） | 写真不可のため線画イラスト化が必要 |

「墨出し」「足場」を直接モチーフにした B2B サイトは、今回の調査範囲では**確認できませんでした（未確認）**。以下は提案（推測）です。

- **墨出し**: スクロールに合わせて水平の基準線が 1 本引かれ、そこに見出しが載る。章の区切りを「線を打つ」動きにする。
- **足場**: 縦横の細い罫線の交点に小さな円（クランプ）を置いた格子。コンテンツが足場に「掛かる」ように配置される。
- **測量**: 十字 + 数値（X/Y 座標、標高）の等幅ラベル。スクロール位置を座標として隅に表示する。
- **図面の表題欄**: 図面右下の表題欄（図番・縮尺・日付）の体裁を、フッターや事例カードのメタ情報に使う。

### 4-2. 信頼感の作り方（確認できた実例）

- **事実の列挙**: 導入社数、受賞、NETIS 登録（アンドパッド、フォトラクション、助太刀）[本文]
- **取引先ロゴ**: 数値を出さずロゴ 30 社で示す（Arent）、ゼネコンのロゴ帯（フォトラクション）[実測]
- **認証マーク**: ISMS などをフッターに（Arent、LayerX、フォトラクション）[本文]
- **電話番号の常設**: ヘッダーに番号と受付時間（助太刀、フォトラクション）[実測]
- **明朝体・生成り背景**: 重みと落ち着き（燈、クラフトバンク）[実測]
- **顧客の声 + 数値 1 つ**: 「作業工数を約 80% 削減」（ニジボックス）、「月 20 時間削減」（フォトラクション）[本文]

### 4-3. 分かりやすさの作り方

- **お悩み別・業種別・立場別の入口**（助太刀、フォトラクション、Procore）
- **工程順の番号リスト**（モンスターラボ）

- **バラバラ → つながる、の図解**（Ramp）
- **CTA を柔らかく**: 「相談してみる」（ROUTE06）、「まずは話を聞きたい」（フォトラクション）

## 5. Linkle 新サイト デザイン方向性 3 案

共通の前提:

- 背景は白〜オフホワイト。本文は 16px 以上、行間 1.8 前後、文字色は濃紺〜墨。#6ccaf1 は面・線・図形に使い、文字には使わない。
- ヘッダーに「資料請求」「相談する」を常設、電話番号も表示。
- 開幕アニメーションは 2 秒以内に本文が読める状態にし、2 回目以降の訪問では省略。OS の「視差効果を減らす」設定で演出を切る。
- スマートフォンではピン留めを解除して通常の縦積みにする。

### 案 A「図面が立ち上がる」— Blueprint / 設計図

| 項目 | 内容 |
|---|---|
| **世界観** | 方眼紙の上で、線が引かれ、寸法が入り、立体になる。「業務を設計して、建てる」会社。精密・誠実・技術的 |
| **配色** | 地 #F7FAFC（青みのある白）／ 方眼線 #6ccaf1 の 12〜15% 濃度 ／ 主色 #6ccaf1 ／ 文字 #0B2540（濃紺）／ 補助 #1E6FA8 ／ アクセント #F5B301（測量マーカーの黄、1 画面 1 か所まで） |
| **フォント** | 和文 **Zen Kaku Gothic New** または **IBM Plex Sans JP** ／ 欧文 **Inter** または **Geist** ／ ラベル・数値 **JetBrains Mono** または **IBM Plex Mono**（すべて Google Fonts） |
| **開幕** | 白い方眼に基準線が十字に 1 本ずつ引かれる → 線画でロゴ（または建物の輪郭）が描かれる → 面が塗られて立体になる → コピーが基準線の上に載る。約 1.8 秒。Igloo の「線画 → 立体」を SVG と CSS で軽く再現 |
| **スクロール構造** | (1) サービス章は左に項目リスト固定・右の図面が切り替わる（Attio 型）。(2) 「導入の流れ」は**横スクロールの工程表**（縦スクロールが横移動に変わるピン留め、ガントチャート風）。(3) 画面隅にスクロール位置を「X: 0240 / Y: 1380」と座標で表示。(4) 章の切れ目で基準線が 1 本引かれる（墨出し） |
| **背景** | 方眼 + 四隅のトンボ + 寸法線。図版はアイソメトリックの線画。章ごとに方眼の縮尺（目の細かさ）が変わる |
| **参照元** | ROUTE06、Arent、スパイダープラス、Buildots、Ramp、Vercel、Igloo Inc |
| **向き不向き** | 建設業との結びつきが最も強く、技術力が伝わる。線が細かくなりすぎると冷たく見えるため、文字サイズと余白を大きく取ることが条件 |

### 案 B「積み上がる」— Soft Blocks / やわらかい 3D

| 項目 | 内容 |
|---|---|
| **世界観** | 明るい空間に、水色の半透明ブロックが浮かび、噛み合い、積み上がって建物や業務フローの形になる。親しみやすく、明快。「むずかしい IT を、積み木のように分かりやすく」 |
| **配色** | 地 #FFFFFF と #F3F9FD ／ 主色 #6ccaf1 ／ 濃淡 #BFE7FA・#2E9BD6 ／ 文字 #14212B ／ 補色アクセント #FF8A65（珊瑚色、Arent に近い暖色を少量）／ 影は青みのグレー |
| **フォント** | 和文 **LINE Seed JP** または **M PLUS 2**（丸みがあり太字が読みやすい）／ 欧文 **Plus Jakarta Sans** または **Manrope** ／ 数値 **Manrope**（すべて Google Fonts） |
| **開幕** | 水色の全面 → 面が複数のブロックに割れて奥へ引き、白背景に散らばる → ブロックがゆっくり集まってコピーの横に 1 つの建物を組む。約 2 秒。ニジボックスの「色面で始まる」+ LayerX の「ブロックが変形する」 |
| **スクロール構造** | 背景の 3D ブロックが**画面に固定されたまま、章ごとに組み替わる**（会社 → サービス → 実績 → 相談で形が変化、LayerX 型）。文章はその手前をカードとして流れる。サービス章は 1 画面 1 サービスのスナップ + 番号ページャー（LIG 型）。ヘッダーはスクロールでピル型に縮む |
| **背景** | 3D はヒーローと章扉に限定し、本文の背後では薄く・静止。ブロックのない区間は淡い水色のグラデーション 1 枚。WebGL が使えない環境では静止画に差し替え |
| **参照元** | LayerX、Arent、Garden Eight（明るい 3D）、Family、Mercury、グッドパッチ |
| **向き不向き** | 40〜60 代・非 IT 層への親しみやすさは最も高い。3D の作り込み次第で品質が決まり、現行サイトの「演出が内容を隠す」課題に戻る危険が 3 案中で最も大きい。3D を背景に留める規律が必須 |

### 案 C「紙面を組む」— Editorial / 誌面と墨

| 項目 | 内容 |
|---|---|
| **世界観** | 上質な会社案内や建築雑誌の誌面。大きな明朝の見出し、細い罫線、縦書き、余白。動きは静かだが、組版の精度で「ディテール」を見せる。落ち着き・格・信頼 |
| **配色** | 地 #FAF8F4（生成り）／ 文字 #1A1A1A（墨）／ 主色 #6ccaf1 は**罫線・下線・小さな色面・図版の 1 色**として限定使用 ／ 補助 #0E3A53（藍）／ グレー #8A8F94 |
| **フォント** | 見出し **Shippori Mincho** または **Zen Old Mincho** ／ 本文 **Noto Sans JP** または **BIZ UDPGothic**（UD 書体で高齢の読者に読みやすい）／ 欧文 **Instrument Serif** または **Newsreader** ／ 番号 **DM Mono**（すべて Google Fonts） |
| **開幕** | 生成りの画面に水色の細い線が 1 本、左から右へ引かれる（墨出し）→ 線の上に縦書きのコピーが 1 行ずつ現れる → 線が罫線としてページの枠組みに変わる。約 1.5 秒。STUDIO DETAILS の「一文だけ見せる」+ Shhh の縦書きと細線 |
| **スクロール構造** | (1) 章扉は巨大な明朝の章番号と見出しがピン留めされ、背景色だけ切り替わる（グッドパッチ型）。(2) 実績は**横にめくる誌面**（横スクロールのピン留め、ページ番号付き）。(3) 縦書きの見出しが左右の端に固定され、本文だけが流れる。(4) 罫線がスクロールに合わせて伸びて表組みを描く |
| **背景** | 生成りにごく薄い紙の質感（ノイズ）。罫線と余白が主役。図版は 1 色刷り風の線画（水色 + 墨の 2 色） |
| **参照元** | mount、Shhh、燈、STUDIO DETAILS（開幕）、クラフトバンク（生成り）、Locomotive、Stripe（縦罫） |
| **向き不向き** | 可読性と信頼感は 3 案中で最も高く、実装負荷と表示速度も有利。「スクロールを壊す」「開幕」の派手さは最も控えめで、発注者の期待に届くかは組版と横めくりの作り込み次第。水色の存在感が弱くなる点も要判断 |

### 3 案の比較

| 観点 | A 図面 | B ブロック | C 誌面 |
|---|---|---|---|
| 建設業との結びつき | 強い | 中 | 中（建築誌の連想） |
| 40〜60 代の読みやすさ | 中（線の量に注意） | 高い | 最も高い |
| 開幕・スクロールの見せ場 | 多い | 最も多い | 控えめ |
| #6ccaf1 の存在感 | 中（線と主色） | 最も強い | 弱い（差し色） |
| 写真なしでの成立 | 線画で成立 | 3D で成立 | 組版で成立 |
| 実装の重さ | 中（SVG 中心） | 重い（3D） | 軽い |
| 現行サイトの課題に戻る危険 | 小 | 大 | 最小 |

**私見**: 発注者の要求（スクロール・背景・開幕・ディテール）と読者の要求（可読性）を両立しやすいのは **案 A** です。建設業との結びつきが説明不要で、演出の大半を SVG と CSS で作れるため、内容を隠さずに見せ場を作れます。案 A を骨格にし、章扉のピン留めと書体の格を案 C から、ヒーローの立体表現を案 B から 1 か所だけ借りる組み合わせも検討に値します。
